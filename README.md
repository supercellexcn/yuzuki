# Yuzuki · ASMR 播放器

自托管的 DLsite ASMR 音声作品管理 / 播放器。扫描本地以 `RJ010xxxx-...` 命名的作品文件夹，自动从 DLsite/HVDB 抓取元数据（标题、声优、社团、系列、发售日、类型标签、封面，以及价格、评分、评论数、销量等会随时间变化的动态数据），提供封面网格浏览、搜索筛选、收藏、播放历史与在线播放。桌面端与手机浏览器共用同一套界面。

## 功能

### 账号与登录

- 所有 `/api/*`（登录接口除外）都需要登录；未登录时前端自动跳转登录页。
- 默认账户 `admin` / 初始密码 `123456`，**首次登录强制修改密码**；登录后可在侧栏用户菜单再次改密。
- 管理后台仅桌面端提供：移动端访问 `/admin` 会被路由守卫直接送回媒体库。

### 媒体库

- **左侧边栏**：站点图标 / 站名、全部社团 / 系列 / 声优 / 标签（带作品数，点击加入筛选）、我的收藏、最近播放、用户菜单、管理功能、设置；可收起为图标栏，移动端为抽屉。筛选弹层内的滚动独立于媒体库（搜索框上滚鼠标不会滚动库页面、列表滚到边界不会带动页面），列表滚动走独立合成层保持流畅，毛玻璃始终生效、外观不变。
- **顶栏**：搜索与排序是两个独立胶囊。搜索匹配 RJ / 标题 / 声优 / 类型标签；RJ 命中该作品的任意语言版本号（翻译版 RJ）也会展示该作品。排序支持入库时间 / 发售日 / 销量，右侧图标切换升序 / 降序。搜索框占位符直接显示当前作品数（随机模式显示随机推荐数）。
- **快捷按钮**：桌面端顶栏为 R（随机推荐）/ M（图片模式）/ T（回到顶部）三个圆形按钮；移动端改为可拖动的悬浮按钮组（首页 / T / M / R），松手吸附到最近一侧并记住位置。
- **封面网格**：类型标签叠加在封面上；信息区显示系列、社团、销量、播放次数、声优。点击卡片进入播放页。
- **筛选**：最多叠加 5 个条件，条件类型可重复（如声优 1 + 声优 2），全部 AND 匹配；「随机」沿用当前筛选条件。
- **加载**：向下滚动自动加载下一页；大屏第一页不足以产生滚动条时会自动补加载，直到页面可滚动或数据取完；搜索 / 筛选 / 清空等请求重叠时只采用最后一次结果并重新校准补页，不会停在「只加载一屏、又没有滚动条」的状态。
- **界面记忆**：每个用户记住筛选条件与排序，登录后还原；同一会话内从播放页返回媒体库时恢复滚动位置。

### 播放

- 播放页展示封面 + 文件列表：点图片打开查看器，点音频播放，点视频**只播放声音**。
- 详情信息区依次显示社团、发售日、系列、销量、**评分**（星标 + 两位小数 + 评论条数）与**价格**（DLsite 日元原价，0 显示「免费」）。评分为 0 显示「暂无评分」、评论数为 0 显示「暂无评论」；这两项或价格为 `null`（本次没抓到）时整行不显示，不会出现「0 日元」这类误导信息。
- **文件列表**按目录树展示，默认全部折叠，使用线性图标，展开 / 收起有动画（时长跟随全局「动画时长」设置）。
- **底部常驻播放条**：封面、标题、上一曲 / 下一曲、快进 / 快退（秒数可配置）、单曲循环、音量；点封面跳回当前播放来源。
- **进度条拖动**：拖动中只预览目标时间，松手才真正跳转；拖动途中不会被播放进度回写，几百 MB 的无损文件远距离拖动也不会出现「进度点跳回」。
- **移动端**：迷你条右上角切换播放 / 暂停；点开为全屏播放器，支持按住下滑退出，播放列表只含当前文件同目录的可播放文件。全屏壁纸上覆盖整屏蒙版，其不透明度 / 模糊跟随「面板透明度 / 面板模糊」设置。
- **Media Session**：锁屏 / 通知栏显示封面、文件名、声优，支持线控 / 蓝牙按键的播放暂停、切歌、快进快退，并同步进度。
- **图片查看器**：左右切换（按钮或方向键）限定在同一目录；可设为封面 / 桌面壁纸 / 移动壁纸。长按图片会在按下的位置就地弹出同样的动作菜单。
- **相关推荐**：文件列表下方横向展示完整作品卡片（不显示推荐理由），可在设置中关闭。

### 收藏

- 四类收藏：作品 / 标签 / 社团 / 声优。
- 作品：封面左上角星标，点击收藏 / 取消。
- 详情页：标签、社团、声优后的 `+` / `−` 收藏或取消（社团为独立方形标签）。
- 「我的收藏」页按四个 Tab 展示；点击收藏的标签 / 社团 / 声优会回到媒体库并按该条件筛选。
- 收藏保存在服务端，多设备同步；长按收藏已移除（长按图片仍会弹出图片动作菜单）。

### 播放历史

- 开始播放即记录；同一作品相邻两次播放间隔 **小于 3 小时**视为同一次「连听」，合并成一条并标出本次连听的文件数，中间播了别的作品则断开。
- 记录每次实际播放时长；历史页支持**列表 / 卡片**两种视图（按设备记住选择）。卡片显示播放时间、本次时长、文件数；图片模式下历史卡片只保留一行时间与时长。
- 顶部的「列表 / 卡片」切换按钮固定贴在页面右端：标题栏在两种视图下都铺满整行，按钮不再随视图宽度变化左右移动；列表内容仍保持 900px 宽度，卡片仍铺满整行。
- 侧栏「最近播放」进入完整历史，分页加载；大屏第一页不足以产生滚动条时（尤其卡片模式）会自动补加载，直到页面可滚动或数据取完；媒体库卡片显示作品累计播放次数。

### 外观

- 全局设置（所有用户 / 设备一致）；桌面端与移动端各一张壁纸，按视口宽度自动切换。壁纸可上传、删除、**停用（保留文件）**，存于 `<数据目录>/wallpapers`。
- **模糊**分三层独立可调（0-100）：壁纸本身；面板亚克力毛玻璃（作品卡片、导航栏、侧栏、用户菜单弹层、底部播放栏、设置卡片、管理页表格等大色块）；标签亚克力毛玻璃（详情页 / 收藏页 / 全屏播放器的声优与类型标签；作品卡片上的标签不参与）。此外全站 Element Plus 控件（输入框 / 下拉 / 按钮）与弹出层（下拉列表 / 对话框 / 抽屉 / 消息框 / 通知 / 各类 popper）统一为苹果液态玻璃质感：半透明底色 + 模糊提饱和 + 多段高光渐变 + 1px 内侧高光描边 + 柔和外投影；控件用标签级轻模糊，弹出层跟随面板模糊，对话框 / 消息框用更大圆角。管理页的搜索框、筛选下拉、操作按钮与修改封面 / 标签编辑等弹窗同样生效。面板 / 标签的模糊与玻璃高光始终生效，无壁纸时模糊作用于面板后方滚动的内容。作品卡片的毛玻璃与其它面板一致，由全局 `html.has-acrylic` 统一开启，滚动过程中不关闭、也不切换承载方式。壁纸本身的模糊是对壁纸层整屏实时 `filter: blur()`，强度即「壁纸模糊」滑杆。
- **透明度**：面板 / 文件列表 / 控件三档独立可调（0-100），始终生效；有壁纸时透出壁纸，没有壁纸时透出页面底色。
- **主题配色**：主题色统一驱动导航栏、hover 框线、播放条、面板底色；声优标签与类型标签独立配色且不透明度各自可调；标签文字统一白色；主题色过暗时按 WCAG 对比度沿原色相自动提亮。
- **卡片尺寸**：小 / 中 / 大 / 自定义宽度；勾选「移动端锁定为每行两列」后，移动端（视口 ≤ 760px）无视卡片尺寸固定两列展示，不勾选则按实际尺寸排布。
- **动画时长**：0-1 秒，全站过渡统一读取；0 即关闭动画。
- **图片模式**：隐藏卡片信息区，只保留封面 / RJ 角标 / 标签；销量以火焰徽标显示在卡片右上边框（≤1000 灰色 1 朵；1000-2999 黄色 1 朵；3000-5999 黄色 2 朵；6000-9999 黄色 3 朵；10000+ 红色 1 朵起、每 3000 加 1 朵最多 3 朵；≥19999 彩色大火 1 朵）。
- 站点图标由 canvas 绘制并声明深色，避免手机夜间模式反色。

### 管理后台

- 仅桌面端；五个 Tab：作品 / 系列 / 社团 / 声优 / 标签。
- **作品管理**：按 RJ / 标题、社团、系列、声优、标签、信息缺失筛选（「信息缺失」是多选下拉，可选项为标题 / 社团 / 封面 / 发售日 / 价格 / 类型标签，勾多项时命中「缺任意一项」的作品）；表格显示封面、评分 / 评论 / 价格、信息缺失项（全齐显示「完整」）、DL 状态与隐藏状态。支持修改封面（从该作品文件里选图，可还原原始封面）、编辑自定义标签、重新同步（DLsite 优先，缺失时用 HVDB 补；封面同理）、隐藏 / 展示。
- **系列 / 社团 / 声优 / 标签**：可隐藏或展示；隐藏会级联到作品。标签里内置一个「全年龄」自定义标签（启动时自动补齐、不可删除）：抓取 DLsite 元数据时，只要「年龄指定」不是 R18 就自动打上；抓不到年龄的作品不打标。它在媒体库「全部标签」弹层里置顶。
- 隐藏的作品不会出现在媒体库、搜索、随机推荐、播放历史、收藏的作品列表和相关推荐中。
- 管理端改名 / 隐藏 / 封面变更后，媒体库下次进入会自动刷新。

### 元数据抓取与补全

- **来源顺序（2026-11 起）**：`product.json`(api2) + `product/info/ajax`(touch) 两个 JSON **并行** → 字段仍缺时用 api1 `product/info/ajax` → 都没命中才降级抓作品页 HTML（announce 预告页）→ HVDB。正常作品只发两个小 JSON（~20KB），**不再抓 730KB 的作品页**；只有 api2 没命中（禁售 / 下架 / 被限制）时才抓 HTML 判定状态，或「标签为空且库里尚未确认分类」「库里没有封面」时额外抓一次作品页（核实「分類」区 / 取 `og:image`，每部只发生一次）。
- **api2 是结构化的首选源**：社团、类型标签（`genres`）、其它语言版本（`language_editions`）、年龄分级（`age_category_string`）、系列（`title_name`）、发售日、封面、日元原价（`official_price`）全部直出，比解析作品页可靠得多；请求固定带 `locale=ja-JP`，保证标题与标签始终是日文原名，不会因为线路语言变化被当成另一部作品。它没有销量（`dl_count`）与两位小数评分（`rate_average_2dp`），这两项由 touch / api1 提供。
- **页面布局兼容**：DLsite 的信息区有新旧两套结构（新：`dt.c-productInfo__key` / `dd.c-productInfo__value`；旧：`#work_outline` 表格），解析器两套都认，改版后不会整片字段掉空。
- **动态数据**（价格 / 评分 / 评论数 / 销量）只存在于 DLsite 的 JSON 接口（作品页 HTML 里没有结构化标记，价格还会随 locale 变成 RMB / USD），touch 与 api1 两个接口都当数据源、缺哪个补哪个：价格取**原价** `official_price`（没有才用售价），评分取 `rate_average_2dp`，评论数取 `rate_count`（评分人数，缺失时退回 `review_count`，再缺就用 api2 的评分分布各档求和）。
- **DL 状态**：每个作品记录上次抓取时 DLsite 的返回状态（`works.fetch_status`），后台作品管理里以标签展示，一眼看出该去哪找信息 —— `ok`（DL 正常返回，api2 命中即算）、`region_blocked`（当前线路所在区域不卖）、`not_found`（DL 上没有此作品，信息来自接口 / 兜底）、`error`（网络异常，下次重试）、空（升级前的老数据，下次扫描写入）。
- **地区禁售不走兜底**：api2 本身受地区限制，美国等海外节点下禁售作品拿不到条目，此时才抓作品页 —— DLsite 对「当前区域不卖」返回 HTTP 200 的限制页（没有信息区，正文一句提示），对「不存在 / 已下架」返回 404。识别为禁售时**立即返回，一个兜底源都不调**，只保留页面 `og:title` 里的标题与社团（禁售页的 `og:image` 是站点通用宣传图，直接丢弃）；避免 HVDB 把字段凑成「看起来完整」，导致换到可用线路后不再重抓、库里留下兜底数据。200 但既无信息区也没命中禁售文案（风控 / 维护 / 改版页）同样不算「DL 正常」，记为 `error` 继续重抓。
- **兜底站点分两档**：HVDB 的**元数据**只在 DLsite 明确返回 404（作品不存在 / 已下架）且官方接口仍补不齐声优 / 标签时才采信，禁售、网络异常、风控页一律不碰；但**封面**是例外 —— DLsite 正常返回（`ok`）或下架（`not_found`）却没有给出任何封面时，允许只从 HVDB 补一张封面（DLsite 原图 api2 → 作品页 `og:image` → api1 已全部尝试过）。`cover_source` 会标成 `hvdb`，日后 DLsite 给出真封面会自动覆盖回来。
- **HVDB 封面地址**：优先读页面里真实的 `<img>`（兼容 `src` / `data-src` / `data-original` 懒加载），都没有才按 HVDB 命名规则拼 URL，**扩展名用 `.webp`**（HVDB 存的是 webp，早期拼 `.jpg` 必然 404，这是「HVDB 有封面却下载不到」的直接原因）。页面完全解析不出内容（风控挑战页 / 改版）时**不再猜 URL**，直接返回空并打日志，避免写入一个必然 404 的地址还让上层以为「已拿到封面」。
- **封面下载失败会回落兜底站**：`fetchWorkMeta` 只负责拿到封面 URL，而 URL 存在不代表能下 —— 老作品图片会被迁移、防盗链会拦、图片域也可能超时。下载失败时自动用 HVDB 再试一次（`downloadCoverWithFallback`），两条路都失败才放弃并打日志（含 URL 与错误原因），下次扫描继续重试。
- **完整性判定先看 DL 状态**：`region_blocked` 无条件重抓（不看字段缺不缺，也不做冷却 —— 它是「换线路就能补」的信号）；`not_found` 且已有标题时元数据不再重复抓（DL 上确实没有），但**缺封面仍会重抓一次**（兜底站点可能有图）；其余按字段缺失判定。
- **完整性只看库里有什么**：标题、社团、声优、封面文件、发售日、价格、至少一个类型标签齐全即算完整；系列、其它语言版本、评分 / 评论数 / 销量都不算必需项。缺任一项 → 下次扫描重抓。
- **声优缺失要区分「没抓到」和「真的没有」**：CG 集 / 漫画这类作品本来就没有声优，不能一律算缺失，否则会每轮永久重抓。用 `works.actors_confirmed` 区分 —— api2 明确返回过 `creaters` 字段，或作品页信息区解析成功，就置 1；此后「声优为空」表示该作品确实没有声优，不再计入缺失。老库该列为 0，所以升级后第一轮扫描会把「有标题但没声优」的作品重抓一次（音声作品基本都能补齐，真的没有的从此不再重试）。
- **类型标签同理，但必须由作品页确认**：有些作品在 DLsite 上只有「作品形式」（音声・ASMR）而没有「分類」（例如 `RJ01289859` 这类全年龄 ASMR 企划、`立ち絵素材` 素材集），api2 会返回**空** `genres`。空数组不能直接当作结论 —— 分类可能只出现在作品页的「分類」区，所以标签为空且库里尚未确认（`works.tags_confirmed = 0`）时会**额外抓一次作品页核实**：页面上有分类就补进库，页面也没有才把 `tags_confirmed` 置 1 定为「该作品没有分类」。确认过之后不再重复抓，未确认的老数据会各重抓一次。
- **兜底数据可被纠正**：`works.cover_source` 记录当前封面来自 `dlsite` 还是 `hvdb`，DLsite 拿到正式封面时会覆盖兜底的封面；声优 / 标签在非禁售状态下每次重抓都整组重建，所以换到可用线路后重扫 / 全库刷新一次，此前被兜底写入的数据会自动被 DLsite 真实数据替换。
- **动态数据每次都会更新**；接口这次没返回时保留库里的旧值，不会被清空。
- **0 不等于没抓到**：`price` / `rating` / `rating_count` 用 `NULL` 表示没抓到、`0` 表示确实免费 / 无评分 / 无评论，后台「信息缺失」不会把 0 当成缺失。
- **动态数据走批量预取 + 缓存**：`maniax/product/info/ajax` 支持逗号分隔一次查多个 RJ（`product.json` 不支持多值），所以扫描 / 全库刷新开始前先按 50 个一批把候选作品的动态数据拉回来写进进程内缓存（`dlsite/dynamicCache.ts`：3 小时有效、上限 2 万条、新一轮预取先清空）；随后逐部流程要同一份数据（touch 动态数据、api1 兜底）时直接命中缓存，不再单独请求。扫描只预取「确实要抓」的作品（新作品 / 信息缺失 / 上次禁售），完整作品本来就会跳过。批量失败只是少了一批缓存，逐部流程照旧单独请求，功能不受影响 —— N 部作品的动态数据请求数从 N 降到 N/50。
- **年龄判定宁可留空也不猜**：api2 的 `age_category` 是数字编码（3 = 成人向，未文档化），真正的可读值在 `age_category_string`（`adult` / `general` / `r15`）。只认这三个已知值，其余留空 → 不打「全年龄」标签，避免把 R18 作品误标。
- **集合字段不被破坏性重建**：声优 / 标签 / 翻译 / 全年龄标记只在 `ok` 与 `not_found` 状态下重建；禁售、网络异常、未知状态一律跳过，不会用空数组把库里已有的数据清空。标量字段（标题 / 社团 / 发售日 / 系列）统一 `COALESCE(NULLIF(?, ''), 旧值)`，没抓到就保持原值。

### 设置

- **自动保存**：鼠标离开控件后立即弹出 5 秒倒计时提示，到时保存生效（纯键盘操作停止修改 1.5 秒后兜底弹出）；点 × 取消本次修改并还原到上次保存状态。
- **壁纸相关设置立即生效**：壁纸模糊拖动即时预览，桌面 / 移动壁纸启停即时预览，且不弹保存提示；没有其他未保存修改时会静默自动保存。
- **系统设置**：源路径（可多条）、扫描层级深度、扫描并发数、每页加载数量、快进 / 快退秒数、DLsite 代理、DLsite URL 模板、封面存储目录、默认封面（无封面作品兜底）。
- **扫描**：立即扫描、进度（含每条线程的实时阶段与**处置结果**：跳过 / 已处理 / 禁售 / 下架 / 失败）、本轮结果汇总、暂停 / 继续、错误列表、已移除文件夹统计。预取阶段显示「预取动态数据 12/30 批」，不会看起来像卡死。
- **扫描性能**：① 开始前一次性把 works 行、原生标签数、声优数、封面文件名读进内存（`buildScanContext`），每部作品的完整性判定都是内存查找，不再逐部查库；② `works.folder_sig` 记录目录树签名（各子目录 `mtimeMs` 的哈希），签名没变就连 `readdir` / `stat` 都跳过；③ 文件表改为**增量比对**（`sameTree`），结构一致时一个字节都不写 —— 之前每轮对 30 万条文件记录「全删 + 全插」，这是「跳过也要跑一两分钟、WAL 疯长」的主因。目录签名对「同名文件内容覆盖」不敏感（只影响文件大小显示），文件增删改名都会触发。
- **每部作品记录上次处置结果**：`works.last_scan_result`（跳过 / 已处理 / 禁售 / 下架 / 失败）与 `last_scan_at` 落库，后台作品管理里以「上次扫描」列展示 —— 「跳过」表示信息已完整、一个请求都没发；「已处理」表示这轮确实请求了 DLsite 并写库。
- **补齐缺失与动态数据**：立即扫描会对「信息不完整」的作品重新抓取，因此换线路 / 挂代理后重扫一次即可补齐之前因地区限制没抓到的内容（DL 状态为「地区禁售」的作品无条件重抓）；「重新下载缺失封面」右侧的「更新评论、评分、销量数据」勾选后，会对**所有**作品按当前线路刷新一次：干净作品只写批量缓存里的价格 / 评分 / 评论数 / 销量，其余作品（含升级前的老数据、封面来自 HVDB 的）整体对齐元数据并用 DLsite 数据覆盖此前的兜底声优 / 标签 / 封面 —— 这也是修复历史污染数据的方式。
- **相关推荐**：开关、扫描完成后自动计算、立即计算与进度。
- **推荐只在数据变化时计算**：计算前先比对「输入指纹」（作品数 + 标题/社团/系列字符总长 + 销量总和 + `updated_at` 最大值 + 声优关联数 + 标签关联数 + 播放次数总和，存 `recommendation_meta.input_signature`）。扫描跳过一部作品只改 `last_scan_*`，不会动 `updated_at`，所以不会触发重算；只有新增 / 删除作品、改元数据、重建声优标签、播放次数变化才会重算。手动「立即计算」是强制重算（调过权重后用），界面会提示「作品数据未变化，已跳过计算」。
- **危险操作**：清空媒体库（删除作品元数据与封面缓存；播放历史与播放次数保留，重新扫描后自动接回；扫描进行中不允许清空）。

### 任务状态推送（SSE）

扫描 / 封面重下 / 推荐计算三类任务的进度不再靠轮询，改为一条 SSE 长连接：

- **端点**：`GET /api/scan/events?token=<JWT>`。原生 `EventSource` 不能自定义请求头，所以走 `?token=`（后端 `authMiddleware` 同时支持 `Authorization: Bearer` 与查询参数）。
- **事件**：连上立刻推 `scan` / `cover` / `recommendation` 三帧全量快照，之后只推有变化的那一类，`data` 为对应任务的完整 JSON（与 `/api/scan/status`、`/cover-status` 完全同构）。
- **合并推送**：后端对所有变化做 100ms 去抖 —— 并发 5 时一秒钟十几条进度回调会被合并成一次广播；任务开始 / 结束走立即推送，终态不会漏。
- **心跳**：每 15 秒一条 `: ping` 注释行，穿越 nginx / 群晖反代 / NPM 的空闲超时。
- **刷新与重连**：任务状态保存在后端进程内存，**刷新页面、断线重连后后端会重推一帧全量快照，状态自然恢复**，前端不需要轮询兜底。唯一会丢状态的情况是后端进程重启（内存清零，任务本身也中断）。
- **断线重试**：后端下发 `retry: 3000`，浏览器 3 秒后自动重连；`?token=` 失效返回 401 时 `EventSource` 会放弃重连（`readyState=CLOSED`），控制台给出提示。
- **兜底接口保留**：`/api/scan/status`、`/api/scan/cover-status` 不删除，调试 / 脚本 / 排障仍可用。
- **连接上限**：同时最多 20 条，超出返回 503，防止标签页堆积。

## Docker 部署

前置：后端需要 Node 22+（`node:sqlite`），Dockerfile 已用 `node:22-alpine`。

1. **准备 `.env`**（复制 `.env.example`）：务必设置 `AUTH_SECRET`（随机字符串，用 `openssl rand -hex 32` 生成）；如需改前端端口可设 `FRONTEND_PORT`（默认 8080）。

2. **挂载 ASMR 源目录**：编辑 `docker-compose.yml`，把后端容器的源目录按 `宿主机路径:容器内路径:ro` 挂载（只读）：

   ```yaml
   backend:
     volumes:
       - ./backend/data:/data        # 数据卷，保留数据库与封面
       - "/你的ASMR目录:/asmr1:ro"     # ← 你的源目录，可加多条
   ```

   `./backend/data` 默认挂到容器 `/data`，本地开发积累的数据库可直接复用。

3. **构建并启动**：

   ```bash
   docker compose up --build -d
   ```

4. **访问与初始化**：打开 `http://<服务器IP>:8080`
   - 默认账户 `admin` / 密码 `123456`，首次登录会**强制修改密码**
   - 「设置」→ 添加源路径（填写**容器内**路径，即上面挂载的 `/asmr1` 等）→ 配置扫描深度、并发数、代理 → 保存并「立即扫描」
   - 若 DLsite 抓不到数据，多半是容器网络无法直连 DLsite，需在设置里配置代理（见上）。

### 更新部署

```bash
docker compose stop backend                              # 先停后端，让 SQLite 的 WAL 合并回主库
cp -a backend/data backend/data.bak-$(date +%Y%m%d)      # 备份（含 covers / wallpapers）
git pull                                                 # 或把改动同步上去
docker compose up -d --build                             # ← 必须带 --build
```

要点：

- **数据库不需要手动迁移**：新增的设置项在后端启动时自动补默认值，废弃项由启动时的迁移清理；数据库本身在 `./backend/data` 卷里，重建镜像不会动它。
- **必须带 `--build`**：`nginx.conf` / `Dockerfile` / `package.json` / `index.html` 这些是**构建时**文件，不在 `src/` 下。只同步 `src/` 或不加 `--build`，容器里跑的还是旧配置 —— 典型症状是「本地正常、NAS 上出现怪问题」（例如上传 413）。
- **别用 `docker compose down -v`**：`-v` 会连数据卷一起删。
- 用域名 / HTTPS 访问时，前面通常还有一层反向代理；**上传体积上限要在那一层也放开**（见上表）。

## 上传体积上限

默认封面与壁纸走 **base64 JSON** 上传，图片上限 **50MB**（base64 后约 66.7MB）。全链路的三个值必须满足「图片上限 < base64 后体积 < 代理 / 后端上限」，改其一要同步改其余：

| 层 | 位置 | 当前值 |
| --- | --- | --- |
| 前端预检 | `frontend/src/views/SettingsView.vue`、`composables/useImageActions.ts` | 50MB |
| 后端接口校验 | `backend/src/routes/settings.ts` | 50MB |
| 前端容器 nginx | `frontend/nginx.conf` → `client_max_body_size` | 75m |
| 后端 express | `backend/src/index.ts` → `express.json({ limit })` | 75mb |

> 若宿主机上还挂了一层反向代理（群晖反向代理 / Nginx Proxy Manager / 自建 nginx 等），**那一层也要放开**（填 `client_max_body_size 75m;`），否则会在到达容器前就被 413 拒绝。注意它看到的是 base64 之后的请求体（约 67MB），所以是 75m 而不是 50m。

## API 摘要

> 除登录接口外，所有 `/api/*` 都需要 `Authorization: Bearer <token>`。

**认证**

- `POST /api/auth/login` 登录；`POST /api/auth/change-password` 改密；`GET /api/auth/me` 当前用户

**作品与媒体**

- `GET /api/works?q=&cond=type:value&sort=&order=&page=&pageSize=` 列表筛选（`cond` 可重复，最多 5 个；`sort` = added / release / sales / title / updated；`q` 命中 RJ / 标题 / 声优 / 标签，以及该作品任意语言版本 RJ）
- `GET /api/works/random?count=&q=&cond=` 随机推荐（遵循筛选）
- `GET /api/works/:rj` 详情（含文件列表与其它语言版本 `translations`）
- `GET /api/works/:rj/recommendations` 相关推荐
- `POST /api/works/:rj/cover` 从作品文件设置封面 `{ file_id }`
- `POST /api/works/:rj/rescan` 重新扫描单个作品文件夹
- `GET /api/media/:rj/:fileId` 媒体流（HTTP Range：单段 206 + `Content-Range`；多段请求合并成单段，不会退化成整文件；越界返回 416 + `bytes */size`；支持后缀段与 HEAD）
- `GET /api/cover/:rj` 封面

**聚合**

- `GET /api/tags` / `GET /api/actors` / `GET /api/circles` / `GET /api/series`（含计数）

**收藏**

- `GET /api/favorites` 分组收藏；`POST /api/favorites` `{ type, value, extra? }`；`DELETE /api/favorites?type=&value=`

**播放与历史**

- `POST /api/plays` 记录播放，返回 `play_id`
- `POST /api/plays/:id/duration` 回写本次实际播放时长 `{ seconds }`
- `GET /api/plays/recent?limit=&offset=` 最近播放（按作品去重）
- `GET /api/plays?page=&pageSize=` 完整历史（按「连听」分组）

**界面偏好**

- `GET/PUT /api/prefs` 筛选条件 / 排序 / 浏览位置

**扫描**

- `POST /api/scan` / `GET /api/scan/status` 扫描与状态（状态含 `fetched` / `skipped` / `outcomes` 汇总，`workers[].result` 为每部作品的处置结果）
- `GET /api/scan/events?token=` 任务状态 SSE 推送（`scan` / `cover` / `recommendation` 三类事件，15 秒心跳）
- `POST /api/scan/pause` / `POST /api/scan/resume` 暂停 / 继续
- `POST /api/scan/redownload-covers` / `GET /api/scan/cover-status` 重下封面；请求体 `{ refresh_stats: true }` 时对所有作品刷新价格 / 评分 / 评论数 / 销量（状态中的 `statsUpdated` 为更新数）
- `POST /api/scan/reset` 清空媒体库（保留历史与计数）

**推荐**

- `POST /api/recommendations/calc` 触发计算；`GET /api/recommendations/status` 任务状态

**设置**

- `GET/PUT /api/settings`
- `GET/POST/DELETE /api/settings/default-cover` 默认封面
- `GET/POST/DELETE /api/settings/wallpaper/:kind` 壁纸（`kind` = `desktop` | `mobile`）

**管理后台**

- `GET /api/admin/works?missing=title,price&…` / `GET /api/admin/works/:rj`（`missing` 为逗号分隔的缺失项，命中缺任意一项的作品；每行返回 `missing` 数组）
- `POST /api/admin/works/:rj/cover` / `POST /api/admin/works/:rj/cover/restore`
- `POST /api/admin/works/:rj/sync` 重新同步元数据与封面（DLsite 优先，HVDB 补）
- `POST /api/admin/works/:rj/hidden` 隐藏 / 展示作品
- `POST/DELETE /api/admin/works/:rj/tags` 自定义标签
- `GET /api/admin/series|circles|actors|tags`；`POST/DELETE /api/admin/tags`（内置「全年龄」标签不允许删除）
- `POST /api/admin/hidden` 通用隐藏（series / circle / actor / tag）

## 已知限制

- 浏览器原生 `<audio>` 对 `flac` / `mkv` 支持有限，首版按常见格式（mp3/m4a/wav + mp4）支持，其余格式在 UI 中可能无法播放。
- `flac` 的远距离 seek 依赖文件内的 `SEEKTABLE`：没有索引时解码器只能按码率估算字节偏移，可能落在错误位置（表现为拖动后位置回退）。服务端不做转码，批量补 `seektable` 是最有效的改善手段。
- DLsite 公开页的部分作品无「販売数」字段，销量留空时 UI 自动隐藏。
- 抓取需网络可达 DLsite，视网络环境需配置代理。
- 管理后台仅桌面端可用；移动端输入 `/admin` 会跳回媒体库。
- **Android 换曲后通知栏媒体控件可能不再出现**：完成一首自动切下一首（或手动切歌）后，音频会正常继续播放，但锁屏 / 通知栏的媒体控件可能不再重建。这是 Chromium 的已知行为（复用同一个 audio 元素换 `src` 时，通知会在换源瞬间被撤掉且重建不可靠），**只影响通知栏控件，不影响播放**。已尝试并**回退**过两种改法，留作记录、避免重复踩坑：
  1. 换曲时主动「释放会话再重建」（`metadata=null` + `playbackState='none'` → 新曲出声后重设）——无效；
  2. 双 `<audio>` 元素交替播放（社区对该问题的常用 workaround）——会导致通知栏显示的曲目与界面实际播放的不一致，以及循环播放。
  如需继续处理，建议先找一台设备确认「换曲瞬间是否存在没有元素在播的空窗」，再决定方向。
